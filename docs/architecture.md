# 🏗️ Архитектура системы

## 📋 Обзор

Социальная сеть построена на микросервисной архитектуре с использованием событийно-ориентированного подхода.

## 🔧 Компоненты системы

### Микросервисы

#### 1. API Gateway (`api_service`)
- **Технология**: FastAPI (Python)
- **Порт**: 8000
- **Назначение**: Единая точка входа для всех клиентских запросов
- **Функции**:
  - Маршрутизация запросов к микросервисам
  - Аутентификация и авторизация
  - Валидация запросов
  - Обработка ошибок
  - Проксирование к User Service и Post Service

#### 2. User Service (`user_service`)
- **Технология**: FastAPI (Python) + gRPC
- **Порты**: 8001 (HTTP), 50052 (gRPC)
- **Назначение**: Управление пользователями и аутентификация
- **Функции**:
  - Регистрация и аутентификация пользователей
  - Управление профилями
  - JWT токены
  - Отправка событий регистрации в Kafka

#### 3. Post Service (`post_service`)
- **Технология**: gRPC (Python)
- **Порт**: 50051
- **Назначение**: Управление постами и взаимодействиями
- **Функции**:
  - CRUD операции с постами
  - Управление комментариями
  - Система лайков
  - Отслеживание просмотров
  - Отправка событий в Kafka

### Инфраструктура

#### PostgreSQL
- **Порт**: 5432
- **Назначение**: Основная база данных
- **Базы данных**:
  - `users_db` - данные пользователей
  - `posts_db` - посты и комментарии

#### Apache Kafka
- **Порт**: 9092
- **Назначение**: Брокер сообщений для событийной архитектуры
- **Топики**:
  - `user-registrations` - события регистрации
  - `post-views` - события просмотров
  - `post-likes` - события лайков/дизлайков
  - `post-comments` - события комментариев

#### Kafka UI
- **Порт**: 8080
- **Назначение**: Web интерфейс для мониторинга Kafka

## 🔄 Взаимодействие компонентов

### Синхронное взаимодействие

```
Клиент → API Gateway → User Service (gRPC)
                   → Post Service (gRPC)
```

1. **Клиент** отправляет HTTP запросы на API Gateway
2. **API Gateway** валидирует запросы и маршрутизирует их
3. **Микросервисы** обрабатывают запросы через gRPC

### Асинхронное взаимодействие

```
User Service → Kafka → Consumer
Post Service → Kafka → Consumer
```

1. **Микросервисы** отправляют события в Kafka
2. **Kafka** доставляет события подписчикам
3. **Consumer'ы** обрабатывают события

## 🔐 Безопасность

### Аутентификация
- JWT токены для аутентификации пользователей
- Токены проверяются в API Gateway
- Передача user_id в gRPC запросах

### Авторизация
- Проверка прав доступа к ресурсам
- Контроль доступа к приватным постам
- Валидация владельца ресурса

## 📈 Масштабируемость

### Горизонтальное масштабирование
- Каждый микросервис может масштабироваться независимо
- Load balancer перед API Gateway
- Kafka обеспечивает надежную доставку событий

### Производительность
- gRPC для быстрого межсервисного взаимодействия
- Асинхронная обработка событий через Kafka
- Индексы в PostgreSQL для быстрых запросов

## 🔧 Развертывание

### Docker Compose
- Все компоненты запускаются через `docker-compose.yml`
- Автоматическая инициализация баз данных
- Health checks для всех сервисов

### Переменные окружения
- Конфигурация через `.env` файлы
- Отдельные настройки для каждого сервиса
- Безопасное хранение секретов

## 🧪 Тестирование
